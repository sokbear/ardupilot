# sbus_capture

«Электронный пилот» для коптера на ArduPilot: Raspberry Pi включается **в разрыв
линии SBUS** между приёмником и полётником и в режиме «захвата» удерживает
визуальную метку в центре кадра, управляя только креном и тангажом.

```
TBS Nano (RX) --SBUS--> [ Raspberry Pi: sbus_capture ] --SBUS--> Полётник (ArduPilot)
                              ^ камера (стабилизирована по pitch+roll гимбалом)
```

Полётник **не дорабатывается** — для него это обычный SBUS-вход.

## Режимы

- **Прозрачный** — кадры оператора ретранслируются в полётник 1:1.
- **Захват** — малина формирует CH1/CH2 (roll/pitch) из видео-PID; CH3/CH4
  (газ/рыскание) и все AUX по-прежнему от оператора.
- Переключение — **тумблером CH7**. При пропадании связи с пультом кадр с
  флагом failsafe пробрасывается дальше, чтобы сработал штатный failsafe FC.

## Структура

| Файл | Назначение |
|------|-----------|
| `config.h`        | каналы, пороги, тайминги, безопасные пределы, усиления PID |
| `sbus.h/.cpp`     | кодек кадра SBUS (decode/encode), совместим с ArduPilot |
| `serial_port.*`   | UART 100000 8E2 через `termios2` |
| `shared_state.h`  | потокобезопасный обмен RX/Vision/TX |
| `pid.h`           | PID с ограничением и анти-виндапом |
| `vision.h/.cpp`   | **заглушка** детектора метки — сюда подключается OpenCV/AprilTag |
| `control.h/.cpp`  | конечный автомат режимов + генерация SBUS (RT-поток) |
| `main.cpp`        | связывание потоков и портов, чтение приёмника |

## Сборка SBUS (на Raspberry Pi / Linux, этап 2+)

```bash
make
```

## Запуск

```bash
sudo ./sbus_capture /dev/ttyAMA0 /dev/ttyAMA1
#                    ^RX от приёмника  ^TX к полётнику
```

`sudo` нужен для realtime-приоритета TX-потока (`SCHED_FIFO`). Без него
программа работает, но с предупреждением и менее стабильным таймингом.

## Аппаратные требования и важные нюансы

1. **Инверсия SBUS.** SBUS — инвертированный сигнal. У UART Pi инверсии нет:
   нужен внешний инвертор на **обе** линии (RX и TX) либо приёмник/конвертер с
   не-инвертированным выходом. Порт конфигурируется как обычный 8E2 100000.
2. **Два UART.** Нужны два отдельных последовательных порта (Pi 4/CM4 имеют
   несколько). USB-serial не рекомендуется — добавляет задержку и джиттер.
3. **«Мягкий failsafe» FC.** ArduPilot считает кадр failsafe, если любой из
   каналов 1–4 имеет значение `<= 875us`. Управляемые каналы зажаты в коридор
   `SBUS_MIN_SAFE..SBUS_MAX_SAFE` (см. `config.h`).
4. **Калибровка осей.** Знаки/поворот «пиксель → (roll, pitch)» зависят от
   установки камеры; настраиваются в `config.h` (`SIGN_*`) или в `control.cpp`
   (поворот 2×2 при азимуте установки ≠ 0).
5. **Камера стабилизирована** по pitch+roll штатным серво-гимбалом ArduPilot —
   тогда `ex,ey` ≈ угловой пеленг и маппинг в наклон прямой.
